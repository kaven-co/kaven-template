# M1.7 — Publicar 4 módulos completos no S3 + criar releases

> **Epic:** M1 | **Agent:** @dev (Bolt)
> **Priority:** P1 — esta é a story de "entrega real" — transforma código em artefato instalável
> **Depends on:** M1.1 (tiers) + M1.2–M1.5 (código real) + M1.6 (CLI gate)
> **Blocks:** nada — é o ponto final do epic

---

## Contexto

Após M1.1–M1.6, os módulos terão código real mas ainda não estarão publicados no marketplace.
Esta story faz o `kaven module publish` para cada um, cria releases no DB do marketplace e
atualiza o DB para refletir os artefatos S3 reais (sem mais `artifactUrl` placeholder).

Esta story **requer marketplace Cloud Run em produção** (503 deve estar resolvido pelo owner antes).
Para testes durante desenvolvimento, usar local dev setup (`feat/local-dev-setup`).

## User Story

**Como** developer que instalou o Kaven no Builder plan,
**Quero** que `kaven module install auth-social` funcione de ponta a ponta,
**Para que** eu possa adicionar Google login ao meu SaaS em minutos.

## Acceptance Criteria

- [ ] `auth-social@1.0.0` publicado: tarball → Ed25519 signed → S3 → release criado no marketplace
- [ ] `storage@1.0.0` publicado: tarball → Ed25519 signed → S3 → release criado
- [ ] `analytics@1.0.0` publicado: tarball → Ed25519 signed → S3 → release criado
- [ ] `email-templates@1.0.0` publicado: tarball → Ed25519 signed → S3 → release criado
- [ ] `payments` atualizado para `1.0.2` no marketplace (tier corrigido de `pro` → `builder`)
- [ ] DB: `artifactUrl` de todos os 5 módulos aponta para S3 real (sem placeholder)
- [ ] `kaven marketplace browse` (prod) lista todos os 5 módulos com tier correto
- [ ] `kaven module install auth-social` (com Builder auth) funciona end-to-end
- [ ] `kaven module install storage` (com Builder auth) funciona end-to-end
- [ ] Smoke test local com `feat/local-dev-setup` antes de publicar em produção

## Checklist de Publicação (por módulo)

```bash
# Para cada módulo (auth-social, storage, analytics, email-templates):

# 1. Dry run
kaven module publish --module modules/{slug} --dry-run

# 2. Verificar module.json (tier, version, injections não vazios)
cat modules/{slug}/module.json | jq '{tier, version, injections: .injections | length}'

# 3. Publicar
kaven module publish --module modules/{slug}

# 4. Verificar release no marketplace
curl https://marketplace.kaven.site/modules/{slug}/releases | jq '.[0]'

# 5. Verificar S3
aws s3 ls s3://kaven-marketplace-artifacts/{slug}/
```
