# M1.3 — Construir módulo `storage` completo

> **Epic:** M1 | **Agent:** @dev (Bolt)
> **Priority:** P1 — storage é dependência natural de quem tem payments (recibos, avatares, attachments)
> **Depends on:** M1.1
> **Blocks:** M1.7 (publish para S3)

---

## Contexto

O módulo `storage` é um shell. O framework tem `apps/api/src/modules/files/` que faz upload básico,
mas não tem abstração de provider (S3/R2/GCS), presigned URLs, ou gestão de buckets por tenant.
Esta story constrói o módulo de storage como provider-agnostic via interface comum.

**O que o core já tem:**
- `files` module: upload simples, metadata no DB — **não mover**, é core
- `FileStorage` model no Prisma — já existe, vamos extender

**O que o módulo adiciona:**
- Provider abstraction (S3, Cloudflare R2, GCS) via `StorageProvider` interface
- Presigned URLs para upload direto do browser
- Organização por tenant (prefixo `tenantId/` no bucket)
- UI: `FileUploader` e `FileGallery` components
- Gestão de lifecycle (expiração, cleanup)

## User Story

**Como** developer usando Kaven,
**Quero** fazer upload de arquivos diretamente do browser para S3/R2/GCS,
**Para que** meus tenants possam fazer upload sem passar pelo servidor da aplicação.

## StorageProvider Interface

```typescript
interface StorageProvider {
  getPresignedUrl(key: string, options: PresignOptions): Promise<string>
  deleteObject(key: string): Promise<void>
  listObjects(prefix: string): Promise<StorageObject[]>
}
```

## Notas Técnicas

- Cloudflare R2 é S3-compatible — o provider S3 já funciona com endpoint R2 via `AWS_ENDPOINT_URL`
- Prefixo obrigatório: `{tenantId}/{userId}/{filename}` — sem isso, tenants podem acessar arquivos uns dos outros
- Presigned URL expira em 15 minutos (configurável via env `STORAGE_PRESIGN_TTL`)
- Não implementar GCS nesta story — apenas interface + S3. GCS pode vir em patch
- O `files` module do core continua existindo — `storage` é uma camada acima, não substituição
