# M1.2 — Construir módulo `auth-social` completo

> **Epic:** M1 | **Agent:** @dev (Bolt)
> **Priority:** P1 — módulo mais solicitado depois de payments; GitHub OAuth já está no framework
> **Depends on:** M1.1 (tier definido)
> **Blocks:** M1.7 (publish para S3)

---

## Contexto

O módulo `auth-social` é atualmente um shell — `module.json` com `"files": []` e `"injections": []`.
O framework **já tem** a lógica de OAuth no core (`apps/api/src/modules/auth/`), incluindo GitHub.
A work desta story é extrair e empacotar essa lógica como módulo instalável, adicionando
providers que o core não tem (Google OAuth).

**O que o core já tem (não duplicar):**
- GitHub OAuth via device code (`/auth/github/callback`) — já implementado
- JWT refresh tokens — core, não mover
- Session management — core, não mover

**O que o módulo precisa adicionar:**
- `@fastify/oauth2` para Google OAuth
- UI components: `SocialLoginButtons` (admin + tenant)
- Rotas: `/auth/google`, `/auth/google/callback`
- Injeção no layout de login existente

## User Story

**Como** usuário final de um SaaS construído com Kaven,
**Quero** poder fazer login com minha conta Google ou GitHub,
**Para que** eu não precise criar senha separada.

## Acceptance Criteria

- [ ] `modules/auth-social/module.json` completo com `files` e `injections` reais
- [ ] `modules/auth-social/backend/routes/` — rotas Google OAuth (`/auth/google`, `/auth/google/callback`)
- [ ] `modules/auth-social/backend/services/google-oauth.service.ts`
- [ ] `modules/auth-social/frontend/components/SocialLoginButtons.tsx`
- [ ] `modules/auth-social/frontend/components/SocialLoginButtons.admin.tsx`
- [ ] Schema Prisma: `SocialAccount` model (userId, provider, providerId, accessToken)
- [ ] `modules/auth-social/prisma/social-auth.prisma` com model `SocialAccount`
- [ ] Injections no `module.json`: import no `app.ts`, rota no router principal, provider no layout
- [ ] `modules/auth-social/tests/` — mínimo: happy path Google login + fallback sem provider configurado
- [ ] README.md com envs obrigatórias (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`)
- [ ] `kaven module publish --dry-run` passa sem erros

## Notas Técnicas

- GitHub OAuth já existe no core — o módulo só adiciona Google
- Apple OAuth: fora de escopo (requer conta Apple Developer $99/ano)
- `@fastify/oauth2` já pode estar no lock file do framework — verificar antes de adicionar
- SocialAccount deve ter FK para User com `onDelete: Cascade`
- Não duplicar lógica de JWT — usar o `auth.service.ts` do core para gerar tokens após OAuth callback
