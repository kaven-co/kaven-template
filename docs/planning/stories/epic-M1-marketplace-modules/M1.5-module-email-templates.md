# M1.5 — Construir módulo `email-templates` completo

> **Epic:** M1 | **Agent:** @dev (Bolt)

> **Depends on:** M1.1

---

## Contexto

O framework tem infraestrutura de email completa (`email-infra`: 4 providers, rate limiting, SNS webhooks),
mas os emails enviados são plain text ou HTML estático inline no código. Este módulo empacota
templates visuais pré-construídos usando React Email.

**O que o core já tem:**
- `NotificationService` com `send()` — funciona, envia plain text
- `Resend` como provider ativo (100/dia free tier)
- `EmailTemplate` enum no schema (WELCOME, PASSWORD_RESET, etc.)

**O que o módulo adiciona:**
- Templates React Email para os 6 emails transacionais do core
- `TemplateRenderer` service que substitui inline HTML
- UI de preview no admin panel (`/admin/email-templates`)
- Variáveis de marca (logo, cor primária, nome do produto) via `tenant.settings`

## User Story

**Como** admin de um SaaS construído com Kaven,
**Quero** que os emails enviados para meus usuários tenham design profissional e minha identidade visual,
**Para que** meu produto pareça enterprise mesmo sendo solo.

## Notas Técnicas

- `react-email` + `@react-email/components` são as dependências — verificar se já no projeto
- `@react-email/render` converte o componente React para HTML string no servidor
- **Sem banco de dados** — templates são código, não dados. Nenhuma migration necessária.
- O `TemplateRenderer` é injetado no `NotificationService` via plugin Fastify (DI pattern do core)
- Preview page no admin: listar todos os 6 templates, seletor de variáveis fake para preview
- Compatibilidade: se módulo não instalado, `NotificationService` usa seu HTML atual (não quebra)
